# Project Rakshak — API Contract

This document outlines the exact request and response schemas for the frontend team to integrate with the backend API.
All examples below reflect **confirmed live responses** from the seeded database (June 2026).

## Base URL
`http://localhost:8000/api/v1`

---

## 1. Predict Transaction Fraud
**Endpoint:** `POST /predict/`
**Description:** Ingests a new transaction, scores it using the ML ensemble (XGBoost + Isolation Forest + SHAP), updates the graph risk, saves to DB, generates alerts if suspicious, and returns the scoring breakdown.

### Request Body (`application/json`)
```json
{
  "sender_account_id": "ACC_0001",
  "receiver_account_id": "ACC_0002",
  "amount": 95000.0,
  "transaction_type": "RTGS",
  "ip_address": "192.168.1.1",
  "device_id": "device_12345",
  "geo_location": "Mumbai, IN"
}
```
| Field | Type | Required | Notes |
|---|---|---|---|
| `sender_account_id` | string | ✅ | Auto-creates account if not found |
| `receiver_account_id` | string | ✅ | Auto-creates account if not found |
| `amount` | float | ✅ | In INR |
| `transaction_type` | string | ✅ | `UPI`, `NEFT`, `IMPS`, `RTGS` |
| `ip_address` | string | ❌ | Optional |
| `device_id` | string | ❌ | Optional |
| `geo_location` | string | ❌ | Optional |

### Response (`200 OK`)
```json
{
  "fraud_probability": 0.6315771341323853,
  "anomaly_score": 1.312,
  "graph_risk": 0.1,
  "final_risk_score": 0.6462308536529542,
  "top_features": [
    { "feature": "F343", "impact": 0.41441 },
    { "feature": "F3901", "impact": -0.22586 },
    { "feature": "F1181", "impact": -0.22021 },
    { "feature": "F745", "impact": -0.19094 },
    { "feature": "F1374", "impact": -0.18841 },
    { "feature": "F1179", "impact": 0.18534 },
    { "feature": "F1035", "impact": 0.1785 },
    { "feature": "F3452", "impact": 0.17652 },
    { "feature": "F3707", "impact": -0.16298 },
    { "feature": "F556", "impact": -0.15837 }
  ],
  "shap_summary": {
    "prediction": 0.6315771341323853,
    "top_features": [
      { "feature": "F343", "impact": 0.41441 },
      { "feature": "F3901", "impact": -0.22586 }
    ],
    "simulated_graph_risk": 0.1
  }
}
```
| Field | Type | Description |
|---|---|---|
| `fraud_probability` | float (0–1) | XGBoost predicted probability of fraud |
| `anomaly_score` | float | Isolation Forest anomaly score (higher = more anomalous) |
| `graph_risk` | float (0–1) | Graph-based risk score — **synced with `shap_summary.simulated_graph_risk`** |
| `final_risk_score` | float (0–1) | Weighted ensemble: `0.4*xgb + 0.3*anomaly + 0.2*graph + 0.1*rules` |
| `top_features` | array | Top 10 SHAP feature impacts, sorted by absolute value |
| `top_features[].feature` | string | Feature name (e.g. `F343`) |
| `top_features[].impact` | float | SHAP value — positive pushes toward fraud, negative pushes away |
| `shap_summary` | object | Full SHAP explanation payload |

## 2. Get Alerts
**Endpoint:** `GET /alerts/`
**Description:** Returns a paginated list of fraud alerts generated by the system.

### Query Parameters
| Parameter | Type | Default | Description |
|---|---|---|---|
| `skip` | int | 0 | Pagination offset |
| `limit` | int | 100 | Max alerts to return |

### Response (`200 OK`)
```json
[
  {
    "transaction_id": "c2575f9a-1a84-4141-91f0-df6722a557df",
    "account_id": "MULE_0000",
    "severity": "HIGH",
    "alert_type": "GENERAL_FRAUD",
    "confidence": 0.8615931398996974,
    "status": "OPEN",
    "id": "cc5f3fff-29a0-4139-bfed-4f048bc8c0f3",
    "created_at": "2026-06-09T04:08:12.285944Z"
  }
]
```
| Field | Type | Description |
|---|---|---|
| `transaction_id` | string (UUID) | The transaction that triggered this alert |
| `account_id` | string | The account flagged (sender) |
| `severity` | string | `HIGH`, `MEDIUM`, `LOW` |
| `alert_type` | string | e.g. `GENERAL_FRAUD` |
| `confidence` | float (0–1) | ML confidence score that triggered the alert |
| `status` | string | `OPEN`, `NEW`, `INVESTIGATING`, `CLOSED_TRUE_POSITIVE`, `CLOSED_FALSE_POSITIVE` |
| `id` | string (UUID) | Alert unique ID |
| `created_at` | string (ISO 8601) | Timestamp of alert creation |

## 4. Get Account Details
**Endpoint:** `GET /accounts/{id}`
**Description:** Returns the profile and risk scores for a specific account.

### Response (`200 OK`)
```json
{
  "account_number": "9999904398",
  "customer_name": "Sai Bose",
  "id": "MULE_0001",
  "risk_score": 0.876700675797162,
  "anomaly_score": 0.7433934782256763,
  "graph_score": 0.95,
  "is_frozen": true,
  "created_at": "2026-06-09T04:08:12.238277Z",
  "transactions": null
}
```
| Field | Type | Description |
|---|---|---|
| `account_number` | string | Bank account number |
| `customer_name` | string | Account holder name |
| `id` | string | Account ID used in transactions (e.g. `ACC_0001`, `MULE_0001`) |
| `risk_score` | float (0–1) | Overall risk score. Mule accounts typically > 0.8 |
| `anomaly_score` | float (0–1) | Behavioral anomaly score |
| `graph_score` | float (0–1) | Graph-based network risk. Mule accounts = 0.95 |
| `is_frozen` | boolean | `true` if account is flagged/frozen |
| `created_at` | string (ISO 8601) | Account creation timestamp |
| `transactions` | array or null | Linked transactions (null unless joined) |

### Error Response (`404 Not Found`)
```json
{ "detail": "Account not found" }
```

## 5. Get Account Graph
**Endpoint:** `GET /graph/{id}`
**Description:** Returns the graph nodes and edges for the given account's local neighborhood for visualization. Graph is built from live `/predict/` calls — seeded DB transactions do not populate the in-memory graph.

### Query Parameters
| Parameter | Type | Default | Description |
|---|---|---|---|
| `depth` | int | 2 | Neighborhood traversal depth |
| `prune_threshold` | float | 0.0 | Minimum edge weight to include |

### Response (`200 OK`)
```json
{
  "nodes": [
    { "id": "ACC_0001", "data": {} },
    { "id": "ACC_0002", "data": {} }
  ],
  "edges": [
    {
      "source": "ACC_0001",
      "target": "ACC_0002",
      "data": { "weight": 95000.0 }
    }
  ],
  "suspicious_paths": [
    ["ACC_0001", "ACC_0002", "ACC_0003"]
  ]
}
```
| Field | Type | Description |
|---|---|---|
| `nodes` | array | Graph nodes in the local neighborhood |
| `nodes[].id` | string | Account ID |
| `nodes[].data` | object | Node metadata (extensible) |
| `edges` | array | Transaction edges between accounts |
| `edges[].source` | string | Sender account ID |
| `edges[].target` | string | Receiver account ID |
| `edges[].data.weight` | float | Transaction amount (INR) |
| `suspicious_paths` | array of arrays | Detected suspicious chains (e.g. mule rings) |

> **Note:** Graph is populated by live `/predict/` calls. After a server restart, the graph is empty until new transactions are processed. Run the simulator (`scripts/simulator.py`) to populate it.

## 6. Real-Time Transactions WebSocket
**Endpoint:** `WS /ws/transactions`
**Description:** Subscribes to real-time transaction updates and their evaluated risk scores. Used to populate the live dashboard.

### Received Message Event (from Server to Client)
```json
{
  "transaction": {
    "sender_account_id": "ACC_0001",
    "receiver_account_id": "ACC_0002",
    "amount": 95000.0,
    "transaction_type": "RTGS",
    "id": "tx_uuid_123",
    "transaction_time": "2026-06-09T04:08:12.000Z"
  },
  "scoring_results": {
    "xgb_probability": 0.6315771341323853,
    "anomaly_score": 1.312,
    "graph_risk": 0.1,
    "final_risk_score": 0.6462308536529542,
    "shap_explanation": {
      "prediction": 0.6315771341323853,
      "top_features": [
        { "feature": "F343", "impact": 0.41441 }
      ],
      "simulated_graph_risk": 0.1
    }
  }
}
```

## 7. Start Simulator
**Endpoint:** `POST /simulate/start`
**Description:** Triggers the background data simulator to start pumping fake transactions into the system. Generates normal, burst, and mule-chain scenarios.

### Response (`200 OK`)
```json
{
  "message": "Simulation started in background."
}
```

## Seeded Account ID Formats
| Pattern | Example | Description |
|---|---|---|
| `ACC_XXXX` | `ACC_0001` | Normal accounts (100 seeded, 4-digit zero-padded) |
| `MULE_XXXX` | `MULE_0001` | Flagged mule accounts (5 seeded, `is_frozen: true`) |

## Transaction Types
`UPI`, `NEFT`, `IMPS`, `RTGS`
