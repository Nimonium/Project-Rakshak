# Project-Rakshak

Enterprise-grade banking fraud intelligence platform designed to detect suspicious accounts, mule account rings, and fraudulent fund movements in real-time.

## Architecture

- **Backend**: FastAPI (Async)
- **Database**: PostgreSQL (SQLAlchemy + asyncpg)
- **Caching & Pub/Sub**: Redis
- **ML Engine**: XGBoost & Isolation Forest
- **Graph Analytics**: NetworkX
- **Explainability**: SHAP
- **Real-time Streaming**: WebSockets

## Setup

### Prerequisites
- Docker & Docker Compose
- `uv` package manager (optional, for local development)

### Deployment with Docker

1. Build and start the services (Postgres, Redis, Backend):
   ```bash
   docker-compose up -d --build
   ```

2. The API will be available at `http://localhost:8000`.
3. Check the API documentation at `http://localhost:8000/docs`.

### Local Development Setup

1. Install dependencies:
   ```bash
   uv pip install -e .
   ```
2. Start the database and Redis using Docker:
   ```bash
   docker-compose up -d postgres redis
   ```
3. Generate Alembic migrations (first time only):
   ```bash
   alembic init alembic
   # Configure alembic.ini with the DB URL
   alembic revision --autogenerate -m "Initial schema"
   alembic upgrade head
   ```
4. Run the server:
   ```bash
   uvicorn backend.app.main:app --reload
   ```

## Advanced ML Pipeline

The new pipeline supports multi-shard dataset loading, hyperparameter tuning via Optuna, and SHAP visualization exports.

1. Ensure dataset shards (`DataSet_part*.json`) are in `backend/data/`.
2. Run the dataset ingestion and feature engineering pipeline:
   ```bash
   python backend/app/ml/feature_engineering/pipeline.py
   ```
   *Reports generated in `artifacts/reports/`*
3. Run the optimized model training (Optuna + Isolation Forest):
   ```bash
   python backend/app/ml/training/train.py
   ```
   *Models saved in `artifacts/models/`, evaluation in `artifacts/evaluation/`*

## Dataset Replay Engine & Stress Testing

To simulate real-world streaming from the loaded dataset, including fraud bursts and mule chains:

1. Ensure the backend is running.
2. Start the simulator in various modes:
   ```bash
   # Normal banking traffic replay
   python scripts/replay_dataset.py --mode normal --speed 1.0

   # Fraud-heavy scenario (rapid fan-outs, mule chains)
   python scripts/replay_dataset.py --mode fraud-heavy --speed 2.0

   # High-throughput stress test
   python scripts/replay_dataset.py --mode stress-test --speed 5.0
   ```

## Observability & Benchmarking

- **Prometheus Metrics**: Available at `http://localhost:8000/api/v1/metrics`. Tracks inference latency, fraud detection rates, and active websockets.
- **Run Benchmark Suite**:
  ```bash
  python tests/benchmarks/test_throughput.py
  ```
  *Generates benchmark report in `artifacts/reports/`*

## SHAP & Graph Visualizations

- **SHAP Plots**: Automatically generated for anomalous predictions and stored in `artifacts/shap/` (e.g., `waterfall_plot.png`).
- **Graph Community Exports**: Louvain partitions and circular money laundering loops are dumped as JSON to `artifacts/graph/`.

## WebSockets

Connect to `ws://localhost:8000/ws/transactions` to listen to a live feed of scored transactions and fraud alerts generated by the system.
